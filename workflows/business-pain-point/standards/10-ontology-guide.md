## 1. 定义与四层结构

技术架构（Ontology）= 把前序识别的数据、价值方向、关键 AI 场景与价值口径，组织成一张**横向分层架构图**，回答"价值场景靠一套什么样的 AI 技术架构兑现"。自下而上四层：

| 层 | 名称 | 作用 |
| :-- | :-- | :-- |
| 第 1 层（底） | **数据来源层** | 支撑上层本体与 agent 的各类业务/外部数据 |
| 第 2 层 | **Ontology 本体知识架构层** | 三框：语义关联本体（存在论）/ 态势感知本体（认识论）/ 仿真决策本体（实践论） |
| 第 3 层 | **Agent Skill 层** | agent 执行任务所调用的能力模块 |
| 第 4 层（顶） | **Agent 行动主体层** | 不同功能的 agent（行动主体），对应关键 AI 场景 |

> 风格：MBB 咨询技术架构页——结构清晰、层级明确、术语专业；**直角框，禁止圆角框**；不堆解释性长文字。

## 2. 第 1 层 · 数据来源层

底层数据来源**按案例公司业务场景生成，不硬编码**。示例（仅示例，按案例取舍）：设备数据、生产数据、交易数据、结算数据、质量数据、供应链数据、客户数据、财务数据、市场数据、外部政策/价格/天气/行业数据。

规则：

- 数据来源必须来自前序 Research、价值树、场景分析中**已识别**的数据（可回溯）。
- 每类数据要能支撑上层某个本体对象或 agent skill（`linked_scenarios`）。
- 数据缺失在过程文件 `data_gaps` 标注，**不在 PPT 暴露内部字段**。

## 3. 第 2 层 · Ontology 本体知识架构层（三框）

**三个本体框必须保留**，框内内容按案例生成（不写死电力行业），每框列 2-4 个案例相关对象/能力，向下连数据、向上撑 skill：

1. **语义关联本体层（存在论）**：定义业务实体、对象、关系、属性——如资产、客户、订单、设备、产品、供应商、市场主体、合同、资源等。
2. **态势感知本体层（认识论）**：定义对运行状态的识别、监测、判断与归因——如异常识别、趋势判断、绩效归因、风险识别、状态评估等。
3. **仿真决策本体层（实践论）**：定义决策、优化、仿真、推荐与执行策略——如计划优化、调度优化、组合优化、策略仿真、动作推荐等。

## 4. 第 3 层 · Agent Skill 层

不同功能 agent 使用的**技能模块**。示例（仅示例，按案例生成）：业务实体与上下文构建、指标树装配与口径映射、规则结构化抽取、数据对齐与尺度统一、偏差解释与量化归因、策略仿真、策略优先级排序与推荐、指标评估与经济性核算、策略解释模型学习。

规则：

- Skill 按案例场景生成，不固定照搬示例。
- Skill 要能解释"**agent 为什么能做这件事**"。
- Skill **不等于**业务场景，也**不等于**系统模块；它是 agent 执行任务所调用的能力。
- 每个 skill 应尽量对应一个或多个 ontology 层能力（`linked_ontology_layer`）。

## 5. 第 4 层 · Agent 行动主体层

最上层是不同功能的 **agent（行动主体）**。示例（仅示例，按案例生成）：采购优化工程师、生产排程优化工程师、质量分析工程师、库存调度工程师、销售策略优化工程师、风险预警工程师、结算与绩效归因工程师。

规则：

- Agent 名称按案例行业与关键场景生成，**不硬编码**。
- Agent 是"行动主体"，要体现它负责什么决策或业务动作（`expected_business_action`）。
- Agent 要对应前序场景分析中的关键 AI 场景（`linked_scenarios`）。
- Agent 数量建议 **4-6 个**；页面空间不足时优先保留最高价值场景对应的 agent。

## 6. 左右侧层级标签

页面左右两侧保留竖向文字标签，体现层级逻辑：

- **左侧（建议）**：智能体调度与技能编排 / 本体知识架构 / 设备控制与数据接入。
- **右侧（建议）**：行动主体 / 物理引擎 / 知识骨架 / 感知接入。

> 若行业非设备密集型，可把"设备控制与数据接入"调整为"业务系统与数据接入"，但**左右侧层级逻辑必须保留**。

## 7. 可溯源与生成规则

- **可溯源**：每个 agent → skill → 本体对象 → 数据来源，均能回溯到 01/03/08/09 的前序内容。
- **非硬编码**：所有层内容按案例生成，禁止套固定行业（尤其电力）模板。
- **agent ↔ 场景对应**：顶层 agent 对应步 08 关键 AI 场景（`linked_scenarios`）。

## 8. 校验闸门

- ⛔ **可溯源**：agent/skill/本体/数据是否都能回溯前序产物？
- ⛔ **层级一致**：四层自下而上是否连贯（数据→本体→skill→agent）、三本体框是否齐全？
- ⛔ **非硬编码行业模板**：是否按案例生成、未套死电力等固定模板？
- ⛔ **PPT 就绪**：四层 + 三框 + 左右标签是否可清晰绘制；**直角框、无圆角**；无内部字段/过程词。
