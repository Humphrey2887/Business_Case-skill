## 1. 核心原则

Research 不是"先有结论再找几条佐证"，而是**先广泛铺开、再收敛出问题假设**。铁律：

- **先 Research，再判断**：任何 Mission Critical 候选都不能在 Research 之前产生（与步 02 v1.8 硬规则 1/2 一致）。
- **公司本体优先**：先搞清客户公司本体（组织类型、核心职责、价值逻辑、靠什么赚钱/最大成本项/核心约束），再看上传材料里的项目场景落在哪个分支——**不得被上传材料牵引**直接立题。
- **行业与公司双研究**：行业研究与公司研究是**两个独立且都必须完成**的模块，不得只研究案例公司而忽略行业，也不得只堆行业趋势而不收敛出行业普遍 Mission Critical。
- **数据诚实**：Research 阶段就要区分"客户真实 / 公司公开 / 行业公开 / 估算 / 内部假设 / 类比 / 不可得"，不得把假设包装成事实（与步 09 数据使用规则一脉相承）。

### 红线（违反即不合格）

- 不得只研究案例公司而忽略行业。
- 不得只堆行业趋势而不形成行业普遍 Mission Critical。
- 不得把上传材料中的项目主题直接当客户 Mission Critical。
- 不得把行业平均数据伪装成客户真实数据。
- 不得使用固定行业流程模板；流程拆分必须说明 `basis`。
- 不得在 Step 01 直接锁死客户最终 Mission Critical；只能形成 Step 02 的候选输入。
- 行业研究、行业普遍 MC、业务流程成本/收益拆分中，凡出现可量化声明（趋势/规模/占比/增减/效率/对比/目标/质量/缺口/金额/周期/排名等，见 SKILL.md 铁律 7），必须落具体数值（企业真实 → 行业平均 → 模拟，并标 `source_type`），不得只给定性。这些数值是 P3/P4 交付页的数据来源。

## 2. 来源覆盖要求

Research 输出**四块内容**（公司研究 / 行业研究 / 行业普遍 MC / 业务流程经济性），依托以下**五类来源**支撑；缺类需在 `data_gaps` 显式标注并说明为何缺：

| 类型 | 内容 |
| :--- | :--- |
| **客户内部信息（上传）** | 客户访谈、业务流程、经营数据、系统现状、组织分工、历史项目材料 |
| **客户公开信息** | 年报、ESG 报告、官网新闻、招投标信息、公告、投资者关系材料、媒体报道 |
| **行业外部信息** | 行业协会、监管机构、政策文件、行业报告、券商/咨询报告、行业趋势、价格走势、技术、监管 |
| **对标案例** | 同行业领先企业、相似业务场景、国内外最佳实践、可比项目收益逻辑 |
| **价值数据** | 成本结构、收入构成、资产规模、运营效率、风险损失、碳排/能耗数据 |

### 来源/工具使用规则（不绑定具体平台工具名）

| 任务 | 推荐来源/工具 | 输出落点 |
| :-- | :-- | :-- |
| 读取上传材料 | 本地文件读取；PDF/DOCX/PPTX/XLSX 对应解析工具 | `company_research`、客户内部 |
| 公司公开信息 | 公司官网、年报、ESG、公告、投资者关系材料、招投标 | `company_research` |
| 行业信息 | 行业协会、监管机构、政策文件、行业报告、券商/咨询报告 | `industry_research` |
| 成本/收益结构 | 年报分部数据、行业成本结构报告、同业公司数据 | `business_process_economics` |
| 对标案例 | 同行业领先企业、可比项目、公开案例 | `industry_research.benchmarks` |
| 数据口径管理 | 结构化 YAML / 表格记录 | `data_ledger` |

**检索顺序建议**：① 读取上传材料 → ② 搜行业信息 → ③ 搜公司公开信息 → ④ 搜成本/收益结构与业务流程经济性 → ⑤ 搜对标案例 → ⑥ 建立数据台账 → ⑦ 输出行业普遍 MC 和客户 MC 初步选项。

> 上传材料的处理：先**归位**（公司战略 / 业务线 / 项目方案 / 产品系统），明确它在公司级命题中的分支位置，仅作 Research 输入与场景证据，**不得直接当 Mission Critical**。

## 3. 案例公司研究标准

围绕"客户公司本体"研究，至少覆盖：

- **公司本体**：组织类型、主营业务、核心职责。
- **公司价值逻辑**：靠什么赚钱、最大成本项、核心资产、关键约束。
- **公司收入结构**：主要收入项与占比。
- **公司成本结构**：主要成本项与占比。
- **公司关键经营数据**：每条标口径与来源类型。
- **公司公开战略或经营压力**。
- **上传材料在公司级命题中的位置**。

优先来源：用户上传材料 → 年报 → ESG 报告 → 官网 → 公告 → 投资者关系材料 → 主流媒体报道 → 招投标信息。

## 4. 所在行业研究标准

行业研究必须**独立完成**，至少覆盖：

- 行业价值逻辑。
- 行业收入模型。
- 行业成本结构。
- 行业利润驱动。
- 行业主要经营压力。
- 行业政策、监管、技术、市场趋势。
- 行业对标案例。
- 行业常见成本高点或收益低点。

优先来源：行业协会 → 监管机构 → 政府政策 → 行业报告 → 券商/咨询报告 → 同行业上市公司年报 → 主流财经/产业媒体 → 可比企业案例。

## 5. 行业普遍 Mission Critical 标准

基于行业研究，输出该行业**普遍最核心**的经营命题。判断方向（枚举）：

| 方向 | 含义 |
| :-- | :-- |
| `cost_down` | 行业普遍问题是成本过高 |
| `revenue_up` | 行业普遍问题是收益过低 |
| `both` | 降本和增收都明显重要 |
| `risk_or_compliance` | 风险/合规成本是关键压力 |
| `asset_efficiency` | 资产效率是关键压力 |
| `uncertain` | 公开信息不足，无法判断 |

写作要求：

- 必须是**行业普遍命题**，不是客户特定命题。
- 一般表达为"降低 XX 成本""提升 XX 收益""提升资产利用效率""降低合规风险损失"等。
- **不要写成解决方案**（如"建设平台""引入 AI 系统"）。
- 每条命题需带 `rationale` 与 `evidence`（point / source / source_type / confidence）。

## 6. 客户业务流程成本/收益拆分标准

> 本节是本步**核心交付之一**。目标：按客户所在行业的价值创造链条拆出主要业务流程，并尽量映射每个流程的成本/收益贡献。

### 正式规则（不得硬编码）

> 按客户所在行业的价值创造链条拆分业务流程，**不使用固定流程模板**。Agent 应从行业研究、公司公开材料、上传材料中识别该行业的核心流程环节，并说明拆分依据。**如果有客户公司的业务流程信息则以客户公司的为优先；若客户公司的业务流程信息与行业的业务流程信息冲突，以客户的为准。**

流程拆分需满足：

1. 覆盖主要成本/收益发生点。
2. 同层流程尽量 MECE，不重复计算。
3. 颗粒度服务于 Business Case，不为拆而拆。
4. 若缺客户真实流程，则先用**行业通用价值链**作为临时假设，并在 `data_gap`（或 `data_gaps`）标注"行业通用价值链假设、待客户确认"。

### 行业流程示例（仅示例，不作为固定模板）

> 以下仅用于理解拆分粒度，**不作为固定模板**：
>
> - 电力行业可参考：燃料采购、运输、入炉、燃烧、发电、并网、交易。
> - 制造行业可参考：采购、生产、质检、仓储、物流、销售、售后。
> - 养殖行业可参考：饲料、育种、养殖、防疫、屠宰、冷链、销售。

### 字段规则

- `process`：流程环节。
- `basis`：为什么这样拆，**必须填**（行业价值链 / 公司年报分部 / 上传材料 / 管理口径 / 行业通用假设）。
- `business_stage`：可选，说明属于上游/中游/下游或业务线。
- `cost_or_revenue_item`：该流程对应的成本/收益项。
- `type`：`cost | revenue | asset | risk`。
- `share_of_total`：占总成本/收入/资产/风险损失的比例。**每条流程必填**（将直接呈现在交付 P4）；缺企业数据时填行业估算并标 `source_type`，不得留空或仅给定性描述。
- `amount` / `unit` / `period` / `entity_scope`：金额或业务量、单位、时间、主体范围。
- `source` / `source_type`：来源与来源类型（`client_real | company_public | industry_public | estimate | internal_assumption | unavailable`）。
- `confidence`：`high | medium | low`。
- `data_gap`：缺口。

规则：

- 如果找不到企业数据，可以用行业数据，但**必须标注**来源类型。
- 如果只有定性判断，也要标 `source_type: unavailable` 或 `estimate`，**不能伪装成事实**。
- 如果流程拆分存在重叠风险，要在 `data_gaps` 或 `note` 里说明。

## 7. 数据台账标准

所有关键数据进入统一 `data_ledger`，逐条记录口径、单位、时间、主体范围、来源类型与可信度，并标注其将被用于下游哪些环节（`used_in`）。

字段：`metric / value / unit / period / entity_scope / source_type / source / confidence / used_in / caveat`。

- `source_type`：`client_real | company_public | industry_public | estimate | internal_assumption | analogy`。
- `used_in`：如 `industry_mc / company_mc / process_economics / value_tree / valuation`。
- `caveat`：口径注意事项 / 可比性限制 / 时间错配等。

数据台账是后续步骤（价值树、价值量化）回溯口径的**单一索引**，缺它则无审计链。

## 8. Research 综合判断

收敛形成 `research_synthesis`，作为步 02 的输入：

- `industry_common_mc`：行业普遍 Mission Critical（引自第 5 节）。
- `client_cost_pressure` / `client_revenue_pressure`：客户成本/收益压力概述。
- `client_process_cost_hotspots` / `client_process_revenue_hotspots`：客户流程成本/收益热点（引自第 6 节）。
- `initial_client_mc_options`：客户 MC **初步候选选项**（按 `cost_down` / `revenue_up` / `both` 给方向 + statement + evidence）。
- `recommended_next_step_input`：交步 02 的建议输入说明。

要求：

- `initial_client_mc_options` 只是给 Step 02 的输入，**Step 01 不直接定最终客户 MC**。
- Step 01 可以提出倾向，但最终客户 MC 选择留给 Step 02。

## 9. 校验闸门

Agent 在输出前必须自查，任一不过则补做 Research：

- ⛔ **公司研究完成**：案例公司本体 / 价值逻辑 / 收入结构 / 成本结构 / 关键约束 / 上传材料定位是否齐全？
- ⛔ **行业研究完成**：行业价值逻辑 / 收入模型 / 成本结构 / 利润驱动 / 趋势 / 对标案例是否齐全且独立完成？
- ⛔ **行业普遍 MC 已生成**：是否给出行业普遍命题方向 + statement + rationale + evidence，且不是客户特定命题、不是解决方案？
- ⛔ **业务流程经济性完成**：是否按价值链拆出流程、每条有 `basis`、未使用固定模板、客户真实流程优先？
- ⛔ **数据台账完整**：关键数据是否都进 `data_ledger`，口径/单位/时间/主体/来源/可信度齐全？
- ⛔ **数据诚实闸门**：每条数据是否标来源类型？是否避免把行业平均/假设当客户真实数据？缺口是否显式（`data_gaps`）？
- ⛔ **不锁死闸门**：是否只形成客户 MC 初步候选，而未在本步锁定最终客户 MC？

## 11. 收资清单标准

> 本节是本步在结构化 Research 内部新增的附加能力「目标企业收资清单（数据收集清单）」的领域标准。
> 收资清单不是新增步骤，而是寄生在本步内部的增量能力：内部收资台账与 `process/01-research.yaml` 并列落盘（仅供内部），不生成任何对外文件；收资项在本步既有用户检查点由顾问口头/对话向客户告知。
> 本节延续第 1 节「数据诚实」与第 6 节「不使用固定流程模板」两条铁律，并将其应用到收资场景。

### 11.1 按行业动态推导（无固定模板）

> 收资清单**按目标企业所在行业价值链与公司实际动态推导**，与第 6 节业务流程拆分同源同理——**不使用固定收资模板**。

推导来源与顺序：

- 从**行业价值链**（第 4 节所在行业研究）识别该行业核心价值创造环节，据此推导每个环节开展分析所需的原始资料与数据。
- 从**公司公开材料**（第 3 节案例公司研究：年报、ESG、公告、投资者关系材料、招投标等）识别公司本体、收入/成本结构与关键经营数据对应的应收资料。
- 从**上传材料**（客户内部信息）识别已知与缺失的资料，补齐分析所需但尚未覆盖的收资项。

核心原则：

- **不使用固定收资模板**：不得套用某个预置的"标准行业收资清单"逐条照搬。每个收资项都必须能追溯到"为完成某块分析而需要"的实际依据，而非模板惯例。这与第 6 节「不得使用固定行业流程模板」一脉相承。
- **客户真实业务流程优先**：WHERE 存在客户真实业务流程信息（上传材料、访谈、经营数据等），**以客户真实流程优先于行业通用价值链**推导收资项；若客户真实流程与行业通用价值链冲突，以客户的为准（与第 6 节「客户真实流程优先」一致）。仅当缺客户真实流程时，才以行业通用价值链作为临时推导依据。
- **示例仅说明粒度，非固定模板**：下方行业价值链示例仅用于**理解推导的颗粒度**，**不作为固定模板**，不得直接照搬为收资项。

#### 行业价值链示例（仅示例，不作为固定模板）

### 11.2 必需/可选分类判据

> 每条收资项都必须标明 `necessity`（必需 / 可选），供目标企业分清优先级。本节给出判据、可执行判定问句清单与判定不变式。

判定的唯一依据是一个内部布尔量 `blocks_core_analysis`（缺失是否阻断核心分析）：

- **必需（`blocks_core_analysis = true`）**：该资料是**核心分析交付物的前置条件**，缺失将**阻断**核心分析、使其无法完成。核心分析交付物指：
  - **公司价值逻辑**（第 3 节：靠什么赚钱 / 最大成本项 / 核心资产 / 关键约束）；
  - **行业价值逻辑**（第 4/5 节：行业价值链、收入模型、成本结构、行业普遍 Mission Critical）；
  - **成本/收益拆分**（第 6 节：按价值链的流程成本/收益贡献拆分）；
  - **初始客户 MC 候选**（第 8 节 `initial_client_mc_options` 的前置条件）。
- **可选（`blocks_core_analysis = false`）**：该资料缺失时**核心分析仍可进行**（既有可得数据已足以得出结论），缺失**仅降低已可得结论的精度/量级**，而不阻断任何核心交付物。

#### 可执行判定问句清单

对每条收资项按顺序自问，任一问句答"是"即判为**必需**（`blocks_core_analysis = true`）；全部答"否"则判为**可选**（`blocks_core_analysis = false`）：

1. **公司价值逻辑闸**：缺了它，是否无法说清客户公司靠什么赚钱、最大成本项、核心资产或关键约束？
2. **行业价值逻辑闸**：缺了它，是否无法完成行业价值链 / 收入模型 / 成本结构，或无法收敛出行业普遍 Mission Critical？
3. **成本/收益拆分闸**：缺了它，是否有某个核心流程环节的成本/收益贡献**根本无法拆分**（而非只是占比不够精确）？
4. **初始客户 MC 候选闸**：缺了它，是否无法形成任何一个可交步 02 的客户 MC 初步候选（`cost_down` / `revenue_up` / `both` 方向 + statement + evidence）？

反向自查（用于确认"可选"判定）：

5. **仅降精度自查**：若某结论**在缺该资料时已能得出**（哪怕用行业公开数据或合理假设，见第 1 节数据诚实），而该资料只会让结论的**精度 / 量级 / 可信度**更高——则它是**可选**，不得误标为必需。

> 判定应针对**该资料对核心分析的实际作用**，而非资料本身的"重要感"。凡是能用行业公开数据或显式假设临时替代、仍能推进核心分析的，一律归为可选（其精度差异由后续客户回填修正）。

#### 判定不变式

`necessity` 与 `blocks_core_analysis` **由同一判定产生，必须严格一致**，禁止出现不一致：

```
blocks_core_analysis = true   ⟺   necessity = "必需"
blocks_core_analysis = false  ⟺   necessity = "可选"
```

即：判定得到 `blocks_core_analysis` 后，`necessity` 由该布尔量**唯一决定**（`true → 必需`，`false → 可选`），二者不得分别独立赋值。若某项缺 `necessity`，须先回填 `blocks_core_analysis` 再据上式补齐；`necessity` 恒取且仅取「必需」「可选」两个中文值之一。

#### 数据诚实回退顺序（Data_Honesty_Fallback）

无数据模式下，分析所需数据按 `SKILL.md` 铁律 6/7 的回退顺序逐级降级选取，**始终取当时可得的最高优先级层级**：

```
企业真实数据（客户提供 / 公开披露的本企业数据）
      │ 不可得 ↓
行业公开数据（行业均值、公开报告、可比公司）
      │ 不可得 ↓
显式模拟 / 假设（明示的估算、行业经验值、情景假设）
```

- 优先用企业真实数据；不可得时降级为行业公开数据；仍不可得时才使用显式模拟 / 假设。
