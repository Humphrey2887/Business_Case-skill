## 1. 核心定义

- **影响因子 (Impact Factor)**：步 03 价值树末端、可量化/可采集/可干预的数据指标（已带单位），是业务一线或系统可直接"动手脚"的控制面板。
- **数据就绪 (Data Readiness)**：一个影响因子要能进入后续价值量化，必须"上秤"——有明确**单位 + 当前基线 + 数据来源**（战略/定性类用可信 proxy）。

本步只回答：**03 的影响因子，哪些数据已就绪、可以拿来测算；哪些缺数据、要标注待补。**

## 2. 步骤定位与核心原则

- **校验而非新造**：在 `process/03-value-tree.yaml` 的 `impact_factors` 上做就绪校验与补齐，**不新造因子、不改价值树结构、不处理痛点**（痛点在 03 定义 / 05 精修 / 06 评分）。
- **不撒胡椒面**：可对核心影响因子聚焦（`quantify_priority` 标 high/mid/low），圈出第 9 步重点测算子集；但不得删除 03 已立的因子，只标优先级与就绪度。
- **数据诚实**：基线取不到就标"待调研"并进 `data_gaps`，不得编造客户真实数据。

## 3. 上秤规范

对每个影响因子（或其 proxy），强制定义：

1. **计量单位**（03 已给；本步敲定 03 标"待确认"的单位）。
2. **当前基线/现状**（取不到标"待调研"）。
3. **数据来源系统**（ERP / CRM / SCADA / MES / 能碳台账 / 人工台账 等）。

**战略价值 / 风险等难直接计量的因子**：允许用 **proxy 或分级评分**上秤（例："样板可复制度" → "已标准化模块占比 % / 单位复制 capex"），proxy 同样要给单位、基线、数据来源。

## 4. 关键影响因子判定标准（Key_Factor_Criteria）

> 本节定义"为什么某些影响因子是**关键影响因子**、某些不是"的明确、可核查、可追溯判据。判定结果通过 `quantify_priority`（high/mid/low）落到 `process/03-value-tree.yaml` 的 `impact_factors` 上，并向下游驱动 P6 关键影响因子总览与场景关键指标。
> **口径权威基准**：本节 `quantify_priority` 标记口径与 PPT映射标准（`ppt-deck-mapping.md`）、场景标准逐项一致；如出现不一致，**以 PPT映射标准为交付组装的权威基准**修正本文件，复核至冲突项数为 0。

### 4.1 四维度取值（每个影响因子各取一个明确取值）

每个影响因子（或其 proxy）**必须**在以下四个可核查维度上**各取得一个明确取值**：

| 维度 | 取值 | 判定说明 |
| :--- | :--- | :--- |
| **(a) 因果贡献度** | 强 / 中 / 弱 | 该因子对其所属**价值方向**的因果贡献强弱；**必附因果链路说明**（改因子 → 价值方向数值变动的传导路径）。 |
| **(b) 数据就绪度** | 就绪 / 不就绪 | **当且仅当** 单位 + 基线值 + 数据源 **三项全部齐备** 记为「就绪」；**缺任一项即记为「不就绪」**。 |
| **(c) 客户可干预性** | 可干预 / 不可干预 | 客户业务一线或系统是否可直接"动手脚"改变该因子取值。 |
| **(d) 量化优先级 `quantify_priority`** | high / mid / low | 由 (a)(b)(c) 三项核心维度命中数量按 §4.3 归类规则得出。 |

### 4.2 三项核心维度定义

**核心维度 = 以下三项**（且取值须命中各自的"核心档"）：

1. **因果贡献度 = 强**
2. **数据就绪度 = 就绪**（单位 + 基线值 + 数据源三项齐备）
3. **客户可干预性 = 可干预**

### 4.3 `high/mid/low` 归类规则

按命中的核心维度项数归类，并据此标记 `quantify_priority`：

| 命中核心维度项数 | `quantify_priority` | 归类 | 处置 |
| :--- | :--- | :--- | :--- |
| **三项全部满足** | `high` | **关键影响因子（Key_Impact_Factor）** | 进入 P6 关键影响因子总览、作为场景关键指标来源 |
| 满足其中两项 | `mid` | 相关/次要影响因子 | **保留在价值树中、不删除**，仅标优先级 |
| 满足一项或零项 | `low` | 相关/次要影响因子 | **保留在价值树中、不删除**，仅标优先级 |

- **同时满足全部三项核心维度** → `quantify_priority = high`，归类为**关键影响因子**。
- **未满足全部三项** → 归类为**相关/次要影响因子**，**保留在价值树中、不予删除**；其中满足两项 → `mid`，满足一项或零项 → `low`。
- 本步**只标优先级与就绪度，不删除 03 已立的因子**（不撒胡椒面 ≠ 删因子）。

### 4.4 high 关键影响因子判定理由记录（强制）

为**每个** `quantify_priority = high` 的关键影响因子记录其**判定理由**，且理由须**逐项列明三项核心维度各自的命中取值**：

```markdown
- 关键影响因子：[名称]（单位：[unit]）→ quantify_priority = high
  - 因果贡献度 = 强（[因果链路说明：改因子 → 价值方向数值变动]）
  - 数据就绪度 = 就绪（单位=[unit]、基线=[值]、数据源=[系统/台账] 三项齐备）
  - 客户可干预性 = 可干预（[客户/系统如何动手脚]）
```

### 4.5 与 PPT 映射标准、场景标准的 `quantify_priority` 口径核对（冲突项数 = 0）

- **与 PPT 映射标准一致**：`ppt-deck-mapping.md` 定义"**关键影响因子 = 价值树中 `quantify_priority = high` 的影响因子子集**"，且 P6 关键影响因子总览**仅纳入 `high`、上限 5 个**；本文件判定口径与之逐字一致——`high` ⇔ 三项核心维度全部命中。**呈现与判定双向一致**：每个 `high` 因子均出现在 P6，P6 不出现任何 `mid`/`low` 因子。
- **与场景标准一致**：场景关键指标全部取自价值树**关键影响因子（`high`）集合**，与关键影响因子一一对应；本文件不得产生与场景标准/价值量化标准相冲突的 `quantify_priority` 取值或归类口径。
- **无 high 因子边界**：若价值树中不存在 `quantify_priority = high` 的影响因子，则下游不生成关键影响因子总览块、输出"缺少 `high` 优先级影响因子"提示，保留价值树其余内容不变。

## 5. 跨行业影响因子-数据源示例库

*(仅示例，帮助把抽象因子落到可取数的系统/台账)*

| 业务领域 | 影响因子（附单位） | 数据来源 |
| :--- | :--- | :--- |
| 燃煤发电 | 燃料低位发热量（MJ/kg）、锅炉含氧量（%）、供电标准煤耗（g/kWh） | 入厂煤质化验、DCS/SIS 生产系统 |

## 6. 质量校验闸门

1. **可测量性闸门**：影响因子（或其 proxy）能否在现有 IT 系统/标准管理流程跑出数据？战略/定性类用 proxy 通过即可；连 proxy 都无数据源才打回。
2. **因果直接性闸门**：改变影响因子是否能短期、直接地引起其所属"价值方向"的数值变动？若中间还隔好几层逻辑，说明 03 因子拆得不够细，回 03 重拆。
