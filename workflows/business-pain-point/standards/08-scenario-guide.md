## 1. 定义

关键场景不能只基于理论价值推导，必须**同时经过现实可行性筛选**。

> 关键场景 = 在**客户可控、数据可得、存在优化空间**的前提下，围绕某个**影响因子**采取**可执行业务动作**，从而改善 Value Tree 上某个 **KPI** 的**业务闭环**。

> 边界与红线：场景是"业务动作闭环"，**不是"上某个系统/平台"**。命名可以带工具（如 "AI+掺烧"），但其内核必须是"针对某影响因子、做某业务动作、改善某 KPI"的闭环，而非交付一个系统。延续全流程反"缺系统"红线。

<!-- @AI_GENERATED -->
> **场景对客户的标准表述模板（交付用）**：面向交付时，每个 AI 场景统一用三段式描述——**『运用[什么 AI/数据技术] → 实现[什么识别/预测/优化功能] → 达成[改善哪个影响因子 / 经营结果]』**；`ai_mechanism` 的客户语言改写须落到此模板，供 PPT 价值树（P7）的场景列小字解释直接引用。

## 2. 识别流程

```
大痛点（含其核心痛点）
  -> 痛点-KPI-影响因子映射
  -> 生成场景机会池
  -> 场景可行性筛选
  -> 场景排除与保留说明
  -> 场景合并与命名
  -> 确定关键场景组合
```

> 起点是第 7 步的**大痛点**：在每个大痛点下，沿其核心痛点 → KPI → 影响因子向下展开场景机会，再过可行性门槛。这样每个场景都可回溯到大痛点与核心痛点。

## 3. 场景筛选门槛

| 筛选门槛 | 判断标准 | 不通过时处理 |
| :--- | :--- | :--- |
| **客户可控性** | 客户是否有权改变计划、采购、运输、掺烧或供应商选择 | 排除或降级为背景约束 |
| **数据可得性** | 所需数据是否可获得、可持续、可合法使用 | 排除或改为前置条件 |
| **优化空间** | 市场机制和客户现状是否存在实际优化空间 | 排除 |
| **业务闭环** | 是否能从预测/分析走到实际动作 | 作为辅助能力，不单独成场景 |
| **价值可量化** | 是否能建立 baseline 和收益测算口径 | 可保留，但标注待验证 |

> 本步对"价值可量化"只判**能不能建 baseline / 收益口径**（可行性层面）；**真正的价值量化在第 9 步**完成。

> `value_status` 严格判定（区分"机制成熟"与"基线已存在"）：
> - **ready**：KPI 的 **baseline 数值当前已存在**（上游第 4 步已给出或可直接调取的现成数值），且收益测算口径清晰。
> - **to_verify**：收益口径清楚，但 **baseline 当前不存在 / 待调研 / 需新建核算口径才能取得**——即便计量机制成熟（如电表可读）也算 to_verify。
> 判据只看"baseline 数值此刻有没有"，不看"机制好不好建"。

## 4. 场景必须满足的条件

场景必须同时满足以下 7 条（与第 3 节门槛是"清单 vs 操作闸门"的互补关系——门槛表给"不通过怎么处理"，本清单给"成立需要哪些"）：

- 对应至少一个核心痛点；
- 映射到 Value Tree 上的 KPI；
- 客户有决策权或调整空间；
- 关键数据可获得、可持续、可合法使用；
- 存在实际优化空间；
- 有可执行业务动作；
- 能进行价值量化或效果验证。

## 4b. 场景关键指标 = 价值树关键影响因子（一一对应与可追溯）

> 本节为**强制规则**，与交付组装权威基准 `ppt-deck-mapping.md`（P6-P7、P9、P10 起逐页规格）及价值量化标准 `09-valuation-guide.md`（§4c `key_indicators` 契约）逐项核对一致，冲突项数为 0；如出现冲突，**以 PPT 映射标准为权威基准修正本文件**。

> 术语：**价值树关键影响因子 = 价值树中 `quantify_priority = high` 的影响因子子集**（判定标准见影响因子标准 `04-kpi-factor-guide.md`：因果贡献度=强、数据就绪度=就绪、客户可干预性=可干预 三项核心维度全部命中）。**场景关键指标**指场景分析中用于测算与表述场景价值的关键指标（即价值量化标准两段式中的 `key_indicators`）。

### 4b.1 一一对应规则（强制）

- **来源闭合**：每个关键场景的**场景关键指标全部取自价值树的关键影响因子集合**——不得引入价值树关键影响因子集合之外的任何指标。
- **一一对应**：场景关键指标与其对应的关键影响因子之间为**一一对应**关系——**无新增、无遗漏、无拆分、无合并**；该场景 `key_indicators` 的指标**数量等于**其对应的价值树关键影响因子数量。
- **三项完全相同**：每个场景关键指标与其来源关键影响因子在 **① 指标名称、② 计量单位、③ 口径定义** 三项上**完全相同**（与价值量化标准 §4c `key_indicators` 一致，亦与 PPT P6 关键影响因子的名称、计量单位一致）。

### 4b.2 可追溯规则（强制）

- 每个场景关键指标**必须标注其来源关键影响因子的标识 `source_factor_id`**，使"场景关键指标 → 价值树关键影响因子"的对应关系可被双向回溯核对。
- 可追溯记录在过程产物（`08-scenario.yaml` / `09-valuation.yaml` 的 `key_indicators[].source_factor_id`）中保留；**交付 PPT 不展示 `source_factor_id` 等内部字段**（延续"过程信息不进 PPT"红线），仅以指标名称+单位与价值树 P6 关键影响因子保持完全一致来体现可追溯。

### 4b.3 越界处理：未对齐即不通过校验（强制）

若某场景关键指标在价值树中**不属于**关键影响因子集合，则该场景**标记为未通过校验**，并按下述任一方式对齐后方可通过；**完成对齐前不保留不一致的关键指标内容**（不得带着越界指标进入交付）：

1. **回溯价值树补齐**：回到价值树（步 03/04），将该指标对应的影响因子**补齐为关键影响因子**（即按 `04-kpi-factor-guide.md` 判定标准命中三项核心维度、标记 `quantify_priority = high`）；或
2. **修正该指标**：修正该场景关键指标，使其**等于已有的某个关键影响因子**（名称、计量单位、口径定义三项相同）。

对齐目标：达到 4b.1（一一对应、数量相等、三项相同）与 4b.2（可追溯标注 `source_factor_id`）的全部要求。

### 4b.4 与价值量化标准的一致性核对（冲突项数 = 0）

| 核对项 | 本场景标准（08） | 价值量化标准（09 §4c） | PPT 映射标准（权威基准） |
| :-- | :-- | :-- | :-- |
| 指标来源 | 全部取自价值树关键影响因子集合 | `key_indicators` 取自价值树关键影响因子 | P9/P10 关键指标须在 P6 关键影响因子集合内 |
| 对应关系 | 一一对应、数量相等 | 指标数量 = 对应关键影响因子数量 | 名称与计量单位与 P6 完全相同 |
| 三项相同 | 名称、计量单位、口径定义完全相同 | 名称、计量单位、口径定义完全相同 | 名称、计量单位完全相同 |
| 可追溯 | 标注 `source_factor_id` | `key_indicators[].source_factor_id` | 以名称+单位一致体现，不展示内部字段 |
| 越界处理 | 标记未通过、对齐前不保留不一致内容 | 同口径 | 不出现未在 P6 关键影响因子集合中的指标 |

> 三方就"场景关键指标 = 价值树关键影响因子"的规则**逐项一致、冲突项数为 0**；任一处出现不一致，以 `ppt-deck-mapping.md` 为权威基准修正本文件与 `09-valuation-guide.md` 后复核至 0。

## 5. 场景数量原则

场景数量绑定 `--length` 深度档位（档位为本工作流自有的三层分级，下表即权威定义；各步对 `--length` 的引用均以此为准）：

| Business Case 规模 | `--length` | 建议场景数量 |
| :--- | :--- | :--- |
| 小型 Business Case | `3min` | 3-4 个 |
| 标准 Business Case | `5min`（默认） | 5-6 个 |
| 大型规划型 Business Case | `10min` / `10min+` | 6-8 个 |

## 6. 跨行业示例库

### 燃煤 Case：最终保留 6 个关键场景

| 序号 | 关键场景 | 对应 KPI | 核心逻辑 |
| :-- | :--- | :--- | :--- |
| 1 | AI+发电量预测 | 采购计划准确性、库存水平、度电燃料成本 | 综合电力市场价格和电网要求，提供精准火电发电量预测，为采购计划、库存安排和掺烧策略提供输入 |
| 2 | 月度策略优化 | 月度采购成本、入炉综合标煤单价 | 挂钩现货价，基于 2 周 / 4 周煤价预测，在低价时段提前囤货或延后采购 |
| 3 | 现货策略优化 | 现货采购成本、进口煤采购成本 | 根据现货补库需求，综合库容量和价格预测，提前或延后采购进口煤 |
| 4 | 打折时段铁路线路优化 | 运输成本、到厂煤成本 | 利用国铁新线路和运费 8/9 折时段，优化运输路径和运输时点 |
| 5 | 供应商优选 | 采购成本、履约稳定性、煤质稳定性 | 结合长协量价、供应商履约、煤质分析等历史情况进行供应商优选 |
| 6 | AI+掺烧 | 供电标准煤耗、度电燃料成本、热经济性 | 发电量不变下优化热经济性，调整各煤种配比，适当增加低价低热值煤；替代人工日度会议决策，自动按明日基础负荷判断加仓比例和加仓量 |

### 燃煤 Case：被排除场景与原因

| 被排除场景 / 方向 | 排除原因 | 方法论归类 |
| :--- | :--- | :--- |
| AI+煤价预测 | 已集成 CCTD，且煤矿信息国家不对外开放，外部关键信息不可得 | 数据可得性不足 / 已有能力重复 |
| 长协/现货/进口煤大比例优化 | 卖方市场，煤企强议价权；煤种配比不变，煤量延续上年量为主 | 优化空间不足 / 客户可控性弱 |
| 基于电量计划自主优化采购计划 | 下月电量计划由电网 25 号确定，电厂直接按电网计划排采购 | 客户决策权不足 |
| 基准煤价优化 | 发改委给基准价，5500 动力煤 675 元/吨 | 政府定价 / 市场机制不可控 |

### 燃煤 Case：痛点到场景示例

**痛点**：综合采购成本高，长协、现货与进口煤配比没有精准测算，最优采购窗口靠人为判断。

**拆解**：
- Critical Mission：降低度电燃料成本
- 价值杠杆：降低入炉综合标煤单价
- 关联 KPI：月度采购成本、现货采购成本、运输成本、到厂煤成本
- 影响因子：煤价预测、库存容量、采购窗口、进口煤补库需求、铁路运费折扣、供应商履约和煤质

**候选场景**：① AI+煤价预测 ② 月度策略优化 ③ 现货策略优化 ④ 长协/现货/进口煤配比优化 ⑤ 供应商优选 ⑥ 铁路线路与打折时段优化

**筛选结果**：
- AI+煤价预测：**排除**（已集成 CCTD，煤矿信息不对外开放，数据可得性不足）。
- 长协/现货/进口煤配比大幅优化：**降级**（卖方市场、煤企议价权强，配比与煤量延续上年量，优化空间有限）。
- 月度策略优化：**保留**（客户可基于 2 周 / 4 周煤价预测调整提前囤货或延后采购）。
- 现货策略优化：**保留**（可结合补库需求、库容量和价格预测调整进口煤采购时点）。
- 供应商优选：**保留**（可基于历史量价、履约和煤质数据优化供应商选择）。
- 打折时段铁路线路优化：**保留**（国铁新线路和运费折扣时段提供明确优化空间）。
