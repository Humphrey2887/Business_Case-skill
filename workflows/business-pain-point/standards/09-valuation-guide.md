## 1. 定义

> 价值量化 = 对第 8 步保留的每个**关键场景**，沿 Value Tree（KPI → 影响因子）建立**测算逻辑**，给出**关键假设**与**待确认数据**，并在数据具备时输出**收益区间**。

价值量化不是"拍一个总数"，而是把每个场景的收益拆成"可被审视、可被回填、可被复算"的结构：公式 + Baseline 来源 + 假设（标数据类型）+ 结果（区间或框架）+ 待确认数据。

> 红线：
> - **数据缺失只输出测算框架，不输出确定收益金额**（不编数）。
> - **类比案例只能作参考，不得作为承诺**。
> - 所有假设必须显式标注数据类型与来源（见第 4 节），不得把"内部假设"当"客户真实数据"用。
> - **口径必须与价值树（第3步）一致**：价值树命题是"xxx 成本节约"，则本步测算口径、瀑布纵轴、明细表"价值提升/总价值创造"列均为**成本节约**口径（实施后成本低于实施前）；命题是"xxx 收益提升"则全程用**收益提升**口径。前后口径不一致视为不合格。

## 2. 通用量化公式

两条通用公式，按场景性质二选一（或组合）：

```
场景价值 = Baseline × 可改善比例 × 可兑现比例
场景价值 = 业务量 × 单位价差 / 成本差 × 捕捉率
```

各因子口径：

| 因子 | 含义 | 取数来源 |
| :--- | :--- | :--- |
| **Baseline** | KPI 的当前基线数值（现状成本/损失/收益规模） | 第 4 步 `04-kpi-factor.yaml` 的 `baseline`；缺失则该场景走"待确认数据" |
| **可改善比例** | 技术/管理上可达的改善幅度（如降本 X%） | 多为内部假设或行业公开口径，必须标注 |
| **可兑现比例** | 扣除现实约束（机制、节奏、执行）后真正能落袋的比例 | 内部假设，保守取值，必须标注 |
| **业务量** | 驱动收益的规模量（采购量/发电量/运输量/用电量等） | 客户真实数据优先 |
| **单位价差 / 成本差** | 优化前后的单位价格或成本差 | 客户真实/行业公开数据 |
| **捕捉率** | 能抓住的价差/机会占比 | 内部假设，必须标注 |

> 公式服务于"可审视"，不服务于"显得精确"。宁可给保守区间 + 透明假设，也不给一个无法回溯的确定数。

## 4. 数据使用规则

| 数据类型 | 使用规则 |
| :--- | :--- |
| **客户真实数据** | 可用于初步测算，**必须标注来源** |
| **行业公开数据** | 可用于参考测算，**必须说明口径** |
| **内部假设** | **必须显式标注**（不得伪装成客户/行业数据） |
| **类比案例** | **只能作为参考，不得承诺** |
| **数据缺失** | **只输出测算框架，不输出确定收益金额** |

> 在 YAML 与文档里，每条假设都带 `data_type`：`client_real` / `industry_public` / `internal_assumption` / `analogy`。

## 4b. 基准优先级规则（企业 > 行业 > 假设）

价值提升测算的 baseline（基准）取数，必须按以下优先级，并在 `baseline_tier` 显式标注用了哪一档：

| 优先级 | `baseline_tier` | 取数来源 | 交付页脚标注 |
| :-- | :-- | :-- | :-- |
| ① 最优先 | `enterprise` | 企业真实基准（client_real，来自 04 `impact_factor_readiness` / 客户台账） | 无需特别声明（真实数据） |
| ② 次选 | `industry` | 行业基准（industry_public，行业报告/同业可比） | 页脚标"参考同业" |
| ③ 兜底 | `assumption` | 显式假设（internal_assumption） | 页脚标"基于假设 / 示意" |

规则：

- **只要企业基准可得，必须用企业基准**；不得在有企业数据时仍用行业值或假设。
- 无企业数据时才退行业基准；行业也无则用显式假设，且该场景通常应判 `to_verify`（baseline 未就绪）、进潜在价值池、不计入总额。
- 用行业/假设档绝不可包装成客户真实数据（延续第 4 节红线）。

## 4c. 每场景两段式内容契约

每个关键场景按**两段式**组织内容（供交付分页：段一→第一页，段二→第二页）：

**段一 · 假设 / 基准 / 口径**
- 关键假设（每条标 `data_type` + 口径/来源）
- 基准数据：`baseline` + `baseline_tier`（企业/行业/假设）+ `baseline_source`
- 口径：`caliber`（成本节约/收益提升）、`unit`、`scope`（主体范围）、`period`（时间口径）

**段二 · 机制 / 闭环 / 关键指标及单位 / 价值提升测算**
- `ai_mechanism`：AI 用什么数据 → 识别什么 → 预测/优化/推荐 → 如何闭环（承接 03/08）
- `closed_loop`：业务动作闭环节点（预测→决策→动作→反馈，供节点化绘制）
- `key_indicators`：关键指标 + **单位**（须满足下方"`key_indicators` 三项相同契约"——与价值树关键影响因子在名称/单位/口径三项完全相同、数量相等、标注 `source_factor_id`）
- 价值提升测算：`formula` 代入 + `estimated_value` 区间；`10min`/`10min+` 给保守/中性/乐观三情景

**完整度规则（`content_completeness`）**：

- `ready` 场景：段一 + 段二**全齐**（page1_full + page2_full）。
- `to_verify` 场景：至少齐**段一 + 段二的机制/闭环**，价值提升测算标"待回填"（回填 baseline 后升级补齐）。

### §4c `key_indicators` 三项相同契约（强制）

两段式段二的 `key_indicators` 与**价值树关键影响因子**（价值树中 `quantify_priority = high` 的影响因子子集，判定见影响因子标准 `04-kpi-factor-guide.md`）须满足以下契约（与场景标准 `08-scenario-guide.md` §4b、PPT 映射标准 P6/P9/P10 起逐项一致）：

- **三项完全相同**：每个 `key_indicators` 项与其来源关键影响因子在 **① 指标名称、② 计量单位、③ 口径定义** 三项上**完全相同**；交付页（P9 明细表、P10 起情景深挖）展示的关键指标名称与计量单位须与 P6 关键影响因子完全相同，**不得出现未在 P6 关键影响因子集合中的指标**。
- **数量相等**：`key_indicators` 的指标**数量等于**该场景对应的价值树关键影响因子数量——一一对应，**无新增、无遗漏、无拆分、无合并**。
- **可追溯**：每个 `key_indicators` 项标注其来源关键影响因子标识 `source_factor_id`（记录于过程产物 `09-valuation.yaml` 的 `key_indicators[].source_factor_id`），使"场景关键指标 → 价值树关键影响因子"可双向回溯；**交付 PPT 不展示 `source_factor_id` 等内部字段**（"过程信息不进 PPT"红线），仅以名称+单位与 P6 一致体现可追溯。
- **越界处理**：若某 `key_indicators` 项在价值树中不属于关键影响因子集合，则该场景**标记为未通过校验**，须回溯价值树补齐对应关键影响因子、或修正该指标使其等于已有关键影响因子，达到上述三项相同与一一对应后方可通过；**完成对齐前不保留不一致的指标内容**。

## 4d. 场景明细表"假设"列两行式写法（强制）

场景明细表（交付页 **P9**）的"假设"列采用**两行式**结构，**除这两行外不得包含其他内容**（与 PPT 映射标准 P9 逐页规格逐字一致）：

**主行（第一行）** = `假设描述` + `净降低率（成本口径）/ 净提升率（收益口径）`：

- 假设描述须**围绕单一关键影响因子（关键指标）**表述，回答"如何通过该关键影响因子实现目标提升"，文字长度 **≤ 50 个汉字**。
- 净降低率/净提升率以**百分比数值**呈现：取值范围 **0.01% – 100.00%**，保留**不超过两位小数**；成本口径用净降低率、收益口径用净提升率（口径与价值树第 3 步命题一致）。

**第二行（括号内）** = `来源类型标注` + `算式 / 推导说明`：

- 来源类型标注**取值限定为 `[企业真实]` / `[行业]` / `[假设]` / `[指引]` 四者之一**（对应 §4 数据类型 client_real / industry_public / internal_assumption / 指引）。
- 给出该数字的**算式或推导说明**（如何由基准、可改善比例、可兑现比例等推导得到净率）。

**多子假设拆分（强制）**：若某关键影响因子的目标提升涉及**多个独立子假设**，则**每个子假设拆为独立行项**、各自遵循两行式写法；**禁止在单一主行内合并多个假设**。

**合规校验（标记待修正）**：出现以下任一情形判为**不合规、标记待修正**：

- 第二行**缺来源类型标注**，或来源类型标注取值不在 `[企业真实]/[行业]/[假设]/[指引]` 四类之内；
- 第二行**缺算式 / 推导说明**；
- 净降低率/净提升率**越界**（超出 0.01%–100.00%）或**小数位数超过两位**；
- 主行假设描述**超过 50 个汉字**，或主行/第二行之外**夹带多余内容**。

**两行式示例**：

```
主行：优化采购窗口择时，降低入炉综合标煤单价，净降低率 3.20%
第二行：（[企业真实] 月度采购量 120 万吨 × 窗口价差 25 元/吨 × 捕捉率 60% ÷ 基准采购成本）
```

## 4e. 情景深挖页契约：测算公式置顶 + 两段式来源（强制）

情景深挖页（交付页 **P10 起**，固定排在场景明细表 P9 之后）须满足以下契约（与 PPT 映射标准 P10 起逐页规格逐项一致）：

### 4e.1 测算公式置顶（强制）

- 情景深挖页**最顶部区域（位于两段式内容之上）**展示该场景**实际选用的测算公式**，公式区块须完整呈现 **① 公式名称、② 公式表达式、③ 该场景关键影响因子的代入值**。
- 顶部公式为本标准**第 2 节两条通用公式中该场景实际且仅选用的一条**（`场景价值 = Baseline × 可改善比例 × 可兑现比例` 或 `场景价值 = 业务量 × 单位价差/成本差 × 捕捉率`），并代入该场景关键影响因子。
- 两段式细化内容（段一假设/基准/口径、段二机制/闭环/关键指标/测算结果）按顺序排布在顶部公式区块**之下**，**不得置于公式之上或穿插其中**。
- 若该场景无法映射到第 2 节两条通用公式中的任一条 → **不渲染该情景深挖页**、输出"缺少可用测算公式"错误提示，保留其余页面输出不受影响。

### 4e.2 两段式来源与可追溯（强制）

- **段一关键指标取自价值树关键影响因子**：段一展示的关键指标全部来自该场景在价值树中对应的关键影响因子集合，可追溯到来源（标识 `source_factor_id`），不引入价值树之外的新影响因子。
- **段二关键假设承接场景明细表（P9）**：段二的关键假设逐项承接同一场景在场景明细表中的假设，可追溯到来源。
- **两段引用均可追溯**：段一（关键指标→关键影响因子）与段二（关键假设→明细表）的引用关系均可双向回溯核对。

### 4e.3 与明细表逐项相等（强制）

- 情景深挖页该场景的关键假设与场景明细表（P9）中同一场景的假设**逐项相等**：数值型取值完全一致、文字型含义一致。
- 出现**缺失 / 取值不等 / 含义冲突**任一情形时 **以场景明细表为准**、标记不一致项并要求修正，**修正完成前该页不通过校验**。

## 5. value_status 绑定与数据回填升级

第 8 步给每个场景判了 `value_status`（严格口径：baseline 数值此刻是否已存在）。本步据此决定"出金额"还是"只出框架"：

| value_status | 本步输出 | result_type |
| :--- | :--- | :--- |
| **ready**（baseline 已存在 + 收益口径清晰） | 出**收益区间** | `quantified` |
| **to_verify**（baseline 待建/待调研） | 只出**测算框架 + 关键假设 + 待确认数据**，不出确定金额 | `framework_only` |

### 数据回填升级机制

`to_verify` 场景并非"永远不能算"——它缺的是 baseline/关键参数。机制为**主动索要、不阻断**：

1. 本步为每个 `framework_only` 场景列出 `to_confirm`（缺哪条 baseline/参数）与 `promotable_to_ready`（回填这些即可量化）。
2. 在**用户检查点**逐条把待确认清单抛给用户请求回填。
3. 用户回填后：该场景 `value_status` 升级 `ready`、`result_type` 改 `quantified`、重算金额，并由"潜在价值池"**移入汇总总额**。
4. 用户未回填的：保留在潜在价值池，**流程不阻断**，可继续进入第 10 步。

> 不得在用户尚未回填时，擅自给 `to_verify` 场景填一个"看起来合理"的 baseline 再算成 ready——那等于编数，违反第 4 节红线。

## 6. 汇总规则

采用 **ready/to_verify 分账**（不混加）：

- **Business Case 总价值** = Σ（所有 `ready` / `quantified` 场景的收益区间）。
- **潜在价值池** = 所有 `to_verify` / `framework_only` 场景列示，**不计入总额**，仅说明"回填 X 后可贡献 Y 量级"。
- 第 5 节回填升级发生后，对应场景**实时从潜在价值池移入总价值**。

> 汇总只对"口径可信"的部分加总，避免用一堆待验证假设堆出一个虚高的总收益。

## 7. 深度与 --length

测算精细度绑定 `--length` 深度档位（档位为本工作流自有的三层分级，下表即权威定义；各步对 `--length` 的引用均以此为准）：

| Business Case 规模 | `--length` | 测算深度 |
| :--- | :--- | :--- |
| 小型 Business Case | `3min` | 单点估算或粗区间，列核心假设 |
| 标准 Business Case | `5min`（默认） | 收益区间 + 主敏感度方向（哪个假设最影响结果） |
| 大型规划型 Business Case | `10min` / `10min+` | 区间 + 敏感度分析 + 情景上下限（保守/中性/乐观） |
