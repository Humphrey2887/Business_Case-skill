## 1. 痛点精修的核心原则

本步对象是 **03 `pain_library` 里已定义的同一批痛点**（按「代号（中文名）」引用），核心目的是把它们打磨成管理层能看懂、且合规的「业务代价」，并回填 `business_consequence` / `outcome_type` / `anti_pattern_ok` 到同一 `pain_id`。

- **不新建痛点、同 id 回填**：本步是精修与校验，不另起痛点编号；实质重复的痛点可合并（用 `merged_from` 留痕），合并后仍是一个 id。
- **不打优先级、不改根因权重**：业务优先级在第 6 步；03 的痛点根因权重（某影响因子内的归因占比）本步不动。
- 一个合格的商业痛点，必须清晰刻画 **【业务情境/作业环节】** 中，因为 **【影响因子】** 的缺陷，导致 **【影响因子/价值方向】** 恶化，最终使企业 **【经营结果】** 付出代价。

> 术语边界：这里的「业务情境/作业环节」是痛点发生的具体作业场合（如采购窗口、出口合规审查），**不是**第 8 步要正式立项筛选的「关键场景」。

## 2. 痛点生成标准公式

Agent 在生成任何痛点时，必须严格套用（或高度符合）以下逻辑句式：

> 在 **【特定的业务情境/作业环节】** 中，
> 由于 **【影响因子 1, 2】** 存在 *[不可见 / 不准确 / 不协同 / 滞后 / 不可归因]* 的问题，
> 导致 **【影响因子 / 价值方向】** *[无法稳定改善 / 波动剧烈 / 不可归因]*，
> 进而影响/损害了最终的 **【七类经营结果之一：收入增长 / 成本降低 / 利润提升 / 资产效率 / 运营效率 / 风险损失 / 战略价值】**。

## 3. 反模式 (Anti-Patterns) 与红线

Agent 在输出前必须进行自我审查，凡触碰以下红线的表达，直接判定为不合格：
* ❌ **「缺药式」痛点（把没有解法当痛点）**：如「缺乏统一的大数据分析平台」、「没有部署 CRM 系统」、「缺乏自动化抓取工具」、「缺乏 XX 能力」。
* ❌ **照搬原话式痛点（未经因果加工）**：「销售跟进太慢」、「碳排放数据算不清楚」、「部门之间沟通不畅」。
* ❌ **断层式痛点（没有指向最终经营结果）**：「由于数据不通，导致报表核对困难」。（必须指出报表核对困难影响了什么成本或收入。）
  - 终局可以落在七类经营结果中的**任一类（含战略价值）**，例如「样板无法标准化，导致零碳园区战略价值无法向全集团产能放大」也算合格；但**必须是具体的经营代价，不能停在中间过程指标**（如「核算困难」「协同不畅」本身不是终局）。

## 4. 跨行业通用示例库

*(Agent 需参考以下跨行业逻辑，对步骤 03 `pain_library` 的痛点做业务化精修)*

| 行业与业务情境 | 影响因子缺陷 | 影响因子/价值方向 恶化 | 最终经营结果影响 | 合格的痛点表达示例 |
| :--- | :--- | :--- | :--- | :--- |
| **B2B 销售线索挖掘** | 企业层级映射缺失、查重滞后 | 线索转化率低 | 增购收入受损 | 在线索清洗分配环节中，由于 CRM 数据库中企业母子公司层级映射不准确且查重机制滞后，导致高质量销售线索转化率低下，进而影响最终的年度增购收入。 |
| **制造企管与碳履约** | 能源台账与内审数据边界不协同 | 产品隐含碳排放量核算失准 | 履约成本推高（成本/风险） | 在应对出口合规审查时，由于内部能源调度台账与 ISO 14001 外部审核数据之间存在边界不协同，导致单吨产品隐含碳排量无法准确归因与核减，进而推高了整体的碳履约成本。 |
| **量化策略研发** | 特征参数盲区、极端敞口难控 | 最大回撤率 (Max Drawdown) 失控 | 绝对收益受损（风险损失） | 在策略回测环节中，由于算法模型对特定特征参数的调优敏感度不可见，且极端行情下的敞口限制不协同，导致策略的最大回撤率无法被稳定控制，进而影响投资组合的绝对收益。 |
| **能源采购与掺烧** | 现货组合缺乏测算、依赖人工窗口 | 入炉综合标煤单价难优化 | 度电成本上升（成本降低） | 在月度与现货采购窗口中，由于长协、现货与进口煤采购组合缺少精准测算，且采购窗口高度依赖人工判断，导致入炉综合标煤单价难以持续优化，进而影响整体度电燃料成本。 |
| **畜牧零碳园区（战略价值类）** | 方案标准化/模块化不足、SOP 沉淀缺失 | 样板可复制度低（已标准化占比低、单位复制 capex 高） | 战略价值无法放大 | 在零碳示范园区向集团其他基地推广的环节中，由于园区方案标准化/模块化程度不足、技术明白卡与 SOP 沉淀不完整，导致样板可复制度低（单位复制 capex 居高不下），进而使零碳园区的战略价值无法向约 8000 万头产能放大。 |

## 6. 交付 .md 痛点列承载结构（价值树 P6-P7 页）

> 本节定义**面向客户的配套交付 .md**（`ppt_result/<project>/<deck>.md`）价值树页（P6-P7，尤其 P7 第二页因果链续接）中，**痛点列**对应的**承载结构（carrier structure）**。
> 目的：`ppt-deck-mapping.md` P6-P7 已要求「痛点列必出」、痛点写「代号（中文名）」，但若交付 .md 没有对应承载槽位，精修后的痛点会在成稿 .md 中整列缺失。本节为交付 .md 显式补出痛点列槽位，使其与 deck 规格一一对应。
> **权威基准**：呈现规则以 [`ppt-deck-mapping.md`](./ppt-deck-mapping.md) P6-P7 为准；本节是其在交付 .md 上的承载落地，不另立新规则。痛点列与 AI 场景三段式解释的完整承载模板见 [`03-value-tree-guide.md`](./03-value-tree-guide.md) §13。

### 6.1 痛点列承载（强制）

- 价值树页 `影响因子 → 痛点 → AI 场景` 因果链中**必须保留痛点列**，**不得被整列删除**或退化为仅留场景。
- 痛点列写「**代号（中文名）**」（如 `P-1（燃料质量识别不足）`），可标根因权重(%)；与本步在 `pain_library` 同一 `pain_id` 上精修的 `P-x` + 中文名一致。
- **保留痛点代号**：`P-x` 代号属 `SKILL.md` §3「过程信息不进 PPT」红线划出的**受控例外**（仅价值树/价值树页痛点列许可），交付 .md 中不视为违规；其余内部代号（场景 `SC-x` id、yaml 键名/枚举值、步骤号等）仍一律禁止。
- 痛点列每项可在其下用一行小字承接本步精修后的业务化解释（`business_consequence` 客户语言改写：在 [业务情境] 中，[影响因子缺陷] 导致 [价值方向恶化]，进而损害 [经营结果]）。

### 6.2 交付 .md 痛点列承载模板（最小槽位）

```markdown
| 痛点列（代号（中文名），可标根因权重%） | 业务化解释（一行，客户语言） |
| :-- | :-- |
| P-1（燃料质量识别不足）（45%） | 在月度采购与入炉环节，因批次燃料质量无法自动识别，燃烧效率不稳定，推高单位燃料成本 |
```

> 说明：痛点列须可逐项追溯到价值树（`03-value-tree-guide.md` §1 第 6–7 层）与本步精修后的 `pain_library`；与 AI 场景三段式解释（『运用[什么技术] → 实现[什么功能] → 达成[什么目标]』）共同构成 P7 因果链的交付 .md 承载，完整模板见 `03-value-tree-guide.md` §13.2。
